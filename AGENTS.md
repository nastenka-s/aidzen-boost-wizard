# Architecture rules
- Keep article cover generation in a server-only kie.ai job adapter using the Pinterest GPT image contract and validated PNG output, so provider changes leave article publication and private cover delivery unchanged.
- Serve completed blog articles through a read-only public projection and client fallback routes merged into the blog catalog, so new article data is live without a frontend deployment while drafts and job payloads remain private.
- Generate deployment RSS with bounded retries and atomically replace only validated complete feeds; retain a valid saved feed with a stale warning during outages so network failures do not block website deployment.
- Pinterest article pins link to the website article URL (campaign identity); Dzen URLs are stored separately and are not pin destinations, because Pinterest RSS import requires the verified domain.
- Keep Dzen publication categories in its tested publication policy; imported articles must not be forced into drafts.
- Keep Pinterest editorial catalogs, astronomical calculations and deterministic visual rotation in the generator's local editorial module so scheduled output is testable independently of paid services.
- Acquire the service-only database lease before Pinterest provider calls; enforce the Moscow-day publication limit atomically and never allow force requests to bypass it.
- Gate article-pin enqueue, claim and finalization with the database eligibility policy and mirror it in local editorial tests; queue eligible published records transactionally and finalize idempotent variants under the shared lease so excluded content, pacing and retries cannot produce unwanted or duplicate pins.
- Build all pin text from curated or calculated briefs and allow AI only to select approved copy variants so generated imagery cannot introduce invented dated events or predictive claims.
- Keep blog keyword catalogs, educational source briefs and tomorrow sky calculations in the local blog editorial module; numerical horoscope facts must be rendered from calculations, not authored by AI.
- Compose tomorrow horoscope prose deterministically from calculated aspects and declared solar whole-sign themes; free-form AI must not introduce dated sky events or unapproved interpretations.
- Keep conversational daily forecast variants and aspect-to-action mappings in the local editorial module, selected by calculated solar houses and Moscow date, so style varies without inventing sky facts.
- Keep competitor research service-only with revoked browser grants and a SQL permission regression test so automated Threads jobs retain access without exposing their inputs.
- Claim a service-only global blog lease and unique Moscow-day category slot before provider calls; persist generated payloads and finalize publication transactionally for safe retries without duplicate daily articles.
- Read generated blog source mutations against one pinned GitHub commit and advance the branch without force; never overwrite concurrently edited source files.
- Keep blog category ordering and Moscow release hours in the service-only database scheduling policy, with SQL regression tests, so scheduled claims share one authoritative timetable.
- Store generated blog covers in a service-write-only private bucket and expose only editorial image filenames through the read-only blog-cover-img endpoint before finalizing RSS; image availability must not depend on website deployment.
- Apply RSS-only CTA changes at feed rendering in its tested footer policy, preserving stored article prose and website CTAs.
- Keep approved manually published RSS articles in the feed's local editorial JSON, merged by slug with scheduled database articles, so manual publication does not consume daily slots or depend on provider calls.
- Share approved manual article metadata under functions/_shared for Dzen and Pinterest; wake article pin processing on enqueue and retain hourly timed retries only while campaign jobs remain pending.
- Keep the user's dated content plan in generate-blog-post/content-plan.json with calculated range events and a blocking pre-publication gate in plan.ts; failing items go to needs_review instead of publishing unverified forecasts.
- Scheduler-authenticated early publication may select only the next unfinished item of the current Moscow day under the existing lease and item identity, preserving normal scheduling and duplicate prevention.
